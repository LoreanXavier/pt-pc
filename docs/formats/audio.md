# Audio

P.T. uses Wwise 2013 (bank version 88) inside Fox Engine's sound layer. All bank media is embedded in the banks; there are no loose `.wem`, no stream packages and no ATRAC9. Cutscene audio is interleaved into some demo streams (`.fsm`). Tools: `tools/sbp.py`, `tools/wwise_bank.py`, `tools/fsm.py`, `tools/audio_dump.py` (full pipeline), `tools/wwise_names.py` (name search). Everything they write goes to `dump/audio/`.

## Fox sound bank package (.sbp)

Little-endian. Same layout GzsTool reads for MGSV (`GzsTool.Core/Sbp`).

| offset | size | field |
| --- | --- | --- |
| 0x00 | 4 | magic `SBPL` |
| 0x04 | 1 | entry count |
| 0x05 | 2 | header size, always 8 + 12 * count |
| 0x07 | 1 | 0 |
| 0x08 | 12 * n | entries: char[4] kind (`bnk\0`, `sab\0`; GzsTool also knows `stp\0`), u32 offset, u32 size |

Payloads start at 0x20 and are 16-byte aligned. In P.T.: `bg_common`, `bgm_common`, `sys_resident` hold one `bnk`; `sfx_common` holds a `bnk` and a 1,440-byte `sab`. No `stp`.

## SAL3 (.sab): voice marker to subtitle table

| offset | size | field |
| --- | --- | --- |
| 0x00 | 4 | magic `SAL3` |
| 0x04 | 4 | record count (18) |
| 0x08 | 16 * n | u64 key, u64 record offset (from the start of the table) |

Record: u32 action count (1), char[4] action kind (`st`, read as subtitle; guess), u32 parameter size (12), 12 parameter bytes (`01000000 0600 6400 00000000`, meaning unknown), 6 unknown bytes (`0800 0100 0000`), the subtitle id (ASCII, zero terminated, for example `tria1000_101010`), then the key again as 6 big-endian bytes.

The key is Fox StrCode64 (with the terminating zero) of a Wwise marker label found in a voice `.wem` (see Media). All 18 keys resolve: 17 labels of the form `TRIA1000_<id>_0_<speaker>` (speaker `caster`, `baby`, `mib`) and `Peephole_Theater`. The subtitle id's StrCode64 low 32 bits, computed on the lowercase id, is the key of the entry in `trial.subp`. Chain at runtime (inferred from the data, not traced): Wwise marker callback, label, StrCode64, `.sab` record, subtitle id, `.subp` entry.

`.subp` as far as needed for the link (guess where noted): u8 1, u8 0x4C, u16 entry count, then entries of u32 key and u32 offset. Entry: 12-byte header (u8 1, u8 0x4C, u8 line count, u8 5 or 7, u16 text size twice, u16 unknown, u8 0 or 0xFF, u8 1), line count pairs of u16 start and end, then UTF-8 text with lines separated by `$`. The times are in 1/100 s (guess: the broadcast entry ends at 96.42 s, its audio lasts 96.9 s).

## Wwise banks

All five banks: `BKHD` version 88, project id 397, language 0 (SFX), feedback flag 1. The bank id is FNV-1 32 of the lowercase bank name (`sfx_common` = 0x5C07F582). `BKHD` is padded so that `DATA` starts 16-byte aligned. Chunks:

| bank | chunks | media | HIRC objects |
| --- | --- | --- | --- |
| Init | BKHD, STMG, HIRC, ENVS | 0 | 66: Bus 22, AuxBus 9, FeedbackBus 1, FxShareSet 3, FxCustom 4, State 27 |
| sys_resident | BKHD, DIDX, DATA, HIRC, STID | 5 | 90 |
| bg_common | same | 6 | 21 |
| sfx_common | same | 291 | 1,030 |
| bgm_common | same | 11 | 64 |

`DIDX` is a list of u32 media id, u32 offset into `DATA`, u32 size. `STID` maps bank ids to names. `ENVS` holds the obstruction and occlusion curves for volume and LPF, all enabled and linear over 0 to 100: volume falls to silence, LPF rises to 100.

HIRC: u32 count, then items of u8 type, u32 size, u32 id, body. Object types in the five banks (1,271 total): Sound 390, Action 301, Event 246, RanSeqCntr 63, FxCustom 52, Attenuation 40, ActorMixer 35, FeedbackNode 34, LayerCntr 29, State 27, Bus 22, MusicTrack 10, AuxBus 9, SwitchCntr 5, FxShareSet 3, MusicSegment 2, MusicRanSeqCntr 1, DialogueEvent 1, FeedbackBus 1. No MusicSwitchCntr. Actions: Play 183, Stop 65, SetGameParameter 19, SetState 10, SetAkProp 10 (Set/Reset Volume, Pitch, BusVolume), Break 10, Seek 2, Pause 1, Resume 1.

`tools/wwise_bank.py` parses every object and checks that each body is consumed to the byte. Its output was compared with wwiser (github.com/bnnm/wwiser) on all 1,271 objects: every id and float matches. Points specific to version 88 that the port must get right:

- NodeBaseParams order: fx (override flag, count, bypass bits, per slot index, fx id, share set flag, rendered flag), override bus id, parent id, two priority flags, prop bundle (u8 count, u8 ids, 4-byte values), ranged prop bundle (min and max pairs), positioning, aux (four flags, four aux bus ids when the last flag is set), advanced settings (12 bytes), state chunk (u32 group count; per group u32 id, u8 sync type, u16 state count, per state u32 state id and u32 instance id), RTPCs (u16 count; per RTPC u32 game parameter, u32 parameter id, u32 curve id, u8 scaling, u16 point count, points of f32 x, f32 y, u32 interpolation), and, because the feedback flag is set, a trailing u32 feedback bus id. Buses end with the same trailing u32.
- Prop values are a float or int union: Loop, TransitionTime and DelayTime are ints (milliseconds for the times), the rest floats (dB for volumes, cents for pitch).
- Positioning: u8 flags (bit 0 overrides parent); if set, u8 2D available, u8 3D available, u8 panner flag when 2D; when 3D, u32 type, u32 attenuation id, u8 spatialized; type 1 is followed by u8 dynamic (game-defined emitter position), type 0 by a path automation block (user-defined paths). The type names are inferred from the data layout, the same way wwiser reads it.
- Curve scaling `dB` (2): stored y is in -1..0 and means 20 * log10(y + 1) dB, with -1 as silence (-96.3 dB); a positive y means -20 * log10(1 - y) dB (0x11A8BB0). Curves interpolate the stored value, then scale it. Shapes Log1 and Exp1 are t(3 - t) / 2 and t(t + 1) / 2 (0x11A8990), the means of linear with Log2 and Exp2. Example: the footstep attenuation reaches -12 dB at 30 m and silence at 50 m.
- Attenuation: u8 cone flag (cone: inside angle, outside angle, outside volume, LPF), five s8 curve slots in the order VolumeDry, VolumeAuxGameDef, VolumeAuxUserDef, LowPassFilter, Spread (slot names follow the Wwise 2013 order; guess), u8 curve count, curves, RTPCs.
- Music: tracks carry sources plus a playlist of play-at, begin trim, end trim and source duration (f64 milliseconds); segments carry duration and entry and exit markers; the random/sequence container has a nested playlist tree. `Play_bgm_corridor_f110` plays a 42.5 s segment once, then loops a 250 s segment; both trim the same five 7-channel stems (0 to 42.5 s and 42.5 to 292.5 s).
- Plugins: sources Vorbis, PCM, ADPCM, Wwise Silence (8), Wwise Tone Generator (6), Wwise Motion Generator (34, in FeedbackNodes, pad vibration; parameters below), one external source (sys_resident, id 1442075084, audio supplied by the game at runtime). Effects: Peak Limiter on Master Audio Bus, RoomVerb on five aux buses (three share sets and one custom), Matrix Reverb and Stereo Delay on one aux bus each; their parameter blocks are decoded.

Wwise Motion Generator parameters (FxCustom object whose id is the source id, plugin 0x01950005, read by 0x5E2950 in the eboot, 0x22 bytes and more): f32 period (s), f32 period multiplier, f32 duration (s), f32 attack, decay, sustain time and release (s), f32 sustain level (dB), u16 duration type (0 period * multiplier, 1 duration, 2 attack + decay + sustain + release), u16 curve count, then per curve u16 point count and points of f32 x (s, 0 to period), f32 y (0 to 1), u32 interpolation. Curve 0 drives the large motor, curve 1 the small motor. All 34 in sfx_common: duration type 0, multiplier 1, two curves, periods 0.3 to 15 s; the ADSR fields are unused. Earlier notes called these sources parameterless; the FxCustom objects were there.

Init bank: volume threshold -80 dB, 256 voices, state groups `chara`, `condition` (arguments of the dialogue event), `cutscene_state` (env_off, bgm_off, bgm_env_off, bgm_off_3s, one unnamed) and `state_common` (splash_screen, in_game, game_over, transitions of 0 to 2 s), eleven game parameters (`rainfall` default 0.5, `rear_rtpc`, `volumeRtpc`, eight unnamed). Bus tree: Master Audio Bus with `environment` (aux buses Lobby, Bathroom, startroom, passage, LFE and two unnamed), an unnamed SFX parent (telephone, Player, ENEMY, Radio, gimmick, BLOOD and two unnamed), an unnamed parent of ME and Music (ducks one unnamed SFX child by 4.5 dB), an unnamed bus with two aux buses (Stereo Delay, RoomVerb), an unnamed parent of four sibling buses whose names differ only in the last character, and one more unnamed bus; plus Master Secondary Bus and Master Motion Bus at the top. Most buses react to `state_common` and `cutscene_state`.

## Media

313 bank media plus 5 demo streams, all 48 kHz. Container: RIFF/WAVE with Wwise codec tags.

| codec tag | codec | count | notes |
| --- | --- | --- | --- |
| 0xFFFF | Wwise Vorbis | 188 | 66-byte `fmt` with Wwise's extension, no Ogg framing; vgmstream decodes it |
| 0xFFFE | PCM, 16-bit | 97 | 24-byte `fmt` (channel mask in the extension), `JUNK`, `data` |
| 0x0002 | Wwise IMA ADPCM | 33 | 4-bit, 36-byte blocks per channel |

Channels: mono 282 (4 of them LFE-only), stereo 4, 6.0 (FL FR BL BR SL SR) 18, 7.0 (plus FC) 5, 7.1 9. In all 32 multichannel files the back and side pairs are bit-identical; this is in the source data (it also holds for the ADPCM file, which is coded per channel). Seven media carry loop points. 31 media carry cue points with `LIST/adtl/labl` labels (the marker labels used by the `.sab`, and names such as `sfx_rid_voice_e_01`).

Decoded with vgmstream-cli r2117 (`-i`, one pass) to `dump/audio/<bank>/<media id>.wav`: 318 of 318, no failures. Durations 0.09 s to 324.8 s, 65.3 minutes in total.

## Demo streams (.fsm)

Sequence of chunks: char[4] tag, u32 size including the 8-byte header. `DEMO`, `SND ` and `END ` chunks continue with an f64 time in seconds. `SYS ` (16 bytes) opens the language copies.

- `DEMO`: cutscene data (camera, motion, skeleton, shader and mesh events, named tracks such as `CAMERA`, `MOVE`, `MOTION`, `SKEL`, `SHADER`, `MESH_EVENT`, `LOCATOR`). Some tracks hold Wwise event ids as u32: gc_p00_010 and gc_p00_160 the 2D footsteps and doors; gc_p00_020, gc_p00_030 and gc_p07_030 pad vibration (FeedbackNode) events; gc_p02_100, gc_p06_010_final and gc_p07_030 `cutscene_state` events; gc_p07_030 also sets and resets the Radio bus volume.
- `SND `: an interleaved Wwise `.wem`. The first `SND ` has an extra 16 bytes after the time: u32 total stream size, u32 2, 8 zero bytes. Concatenating the payloads gives the complete RIFF file.
- `END `: end time.

Streams with audio (all Wwise Vorbis 7.1): gc_p00_020 (14.4 s), gc_p00_030 (8.1 s), gc_p02_100 (38.0 s, a repeated number chant), gc_p07_030 (21.9 s), and `#Eng/gc_p06_010_final` (148.5 s, the ending). The base gc_p06_010_final carries no audio; the English copy is the base plus a `SYS ` chunk and 30 `SND ` chunks.

## .sdf and .evf

Both are binary fox2 DataSet files (format in `fox2.md`).

- `sh_common_sound.sdf`: one `SoundDataFileInfo` with `loadBanks` = sys_resident, bg_common, sfx_common, bgm_common; `prepareBanks` and `prepareEvents` empty. `resident_common_sound.fox2` points to it through a SoundPackage.
- `gc_p04_270_snd.evf`: demo event timeline, `EventDataUnit` entities (`eventName` ExecCommand, `paramString` commands) with `TimeSection` start and end frames. It creates the effect `fxsd_sh_ene_fs01_f040.vfx` on shot `konShotCamera1`, whose sound node posts `Play_ene_fs_f040_01`. `gc_p06_010_light_bc.evf` (ending) holds lighting only.
- `fxsd_*.vfx` (40 files in resident, hallway and hallway_maze_C fpkd): Fox effect files with a sound node; the event name is stored as u16 length plus text.

## Event names

Wwise ids of events, buses, states, switches, game parameters and banks are FNV-1 32 of the lowercase name; other object ids are not name hashes. `audio_dump.py` hashes candidate strings from the Lua scripts, all fpk/fpkd contents, the fox2 name list (`dump/fox2/names.txt`), eboot strings, wem marker labels and the `.sab`, then derives variants (Play/Stop swaps, number, token and suffix variants). `wwise_names.py` searches the rest with paired constraints (a Play and a Stop on the same target, a SetState event and its state) that must satisfy two independent 32-bit hashes, meeting in the middle over an English word list plus game tokens.

Result: 186 of 247 events named (87 confirmed: a verbatim game string hashes to the id; 99 likely: derived variant, paired search, or binary-noise string); 230 of 320 hashed ids overall. Unnamed: 60 events and the dialogue event, 15 buses, 8 game parameters, 3 effect share sets, 2 switches (Material values besides wood, tile, conc, BLOOD), 1 state.

Naming pattern: `Play_`/`Stop_` + category (`sfx`, `voice`, `bgm`, `bg`, `radio`, `sys`, `plr`, `ene`, `man`, `tel`, `hint`) + subject + optional `_NN`, `_lp` (loop), `_2d` (2D variant), `_s`/`_m`/`_l` (size), `fNNN` (hallway floor id); `Set_state_<state>`, `Set_rtpc_<parameter>_<value>`.

Where events come from: Lua (`GameSystem.SoundPostEvent`, `CallBGM`, `StopBGM`, `IsPlayingBGM`; `SoundDaemon.RegisterAnimEvent` for the player's motion events: FOOT_GROUND_L/R `Play_plr_footstep_wk_l/r`, FOOT_LEAVE_L/R `Play_plr_footstep_lv_l/r`, FOOT_CREAK `Play_plr_footstep_creak`, and two RATTLE names without an event), fox2 trap parameters (`soundId`), SoundSource `eventName`, SoundAreaParameter `ambientEvent`, `fxsd_*.vfx`, eboot immediates (62 instruction sites confirmed by disassembly, most in 0x1253000 to 0x128A000, usually loaded into an argument register right before an indirect call), `ShGimmick_layers.mtar` motion tracks (12 ids) and demo stream tracks.

## Running

`python tools/audio_dump.py` runs everything from `dump/chunk1`, `dump/fpk`, `dump/lua`, `dump/elf/eboot.elf`, `dump/strings` and `dump/fox2/names.txt` (about 30 s with 16 threads). It needs numpy, soundfile, capstone and vgmstream-cli (`--vgmstream`, default `C:\Tools\vgmstream\vgmstream-cli.exe`); `--skip-decode` reuses `media.json`. Name search results (`dump/audio/name_search*.json`, each name re-checked against its hash) are merged when present. `python tools/wwise_names.py --names dump/audio/names.json --events dump/audio/events.json --media dump/audio/media.json --candidates dump/audio/name_candidates.txt --english 30000 --out dump/audio/name_search.json` extends that file (the English list needs the wordfreq package). If `dump/audio/asr.json` exists, its transcripts are copied into the media entries.

### Decoders

- PCM (`0xFFFE`): interleaved s16.
- Wwise IMA ADPCM (`0x0002`): each channel has its own 36-byte block per frame (u16 sample, u8 step index, u8 reserved, 32 data bytes). A block gives 64 samples: the header sample, then 63 nibbles, low nibble first; the last nibble is not used. Delta is `((2 * (n & 7) + 1) * step) >> 3`, negated when `n & 8`, clamped to s16, step index clamped to 0..88.
- Wwise Vorbis (`0xFFFF`, 66-byte `fmt`): the `vorb` block follows the 24-byte WAVEFORMATEXTENSIBLE part. `vorb` +0x00 sample count, +0x10 setup packet offset and +0x14 first audio packet offset (both relative to `data`), +0x28 and +0x29 the small and large block size exponents (8 and 11 in all P.T. files). Packets are u16 size plus payload (no granule). The setup packet holds 10-bit codebook ids into the aoTuV 6.03 codebook library and a trimmed setup (no floor, residue and mapping type fields, no window and transform fields); it is rebuilt into a standard Vorbis setup header as ww2ogg and vgmstream do. Audio packets drop the packet type bit and, for long blocks, the previous and next window flags; the rebuild inserts them (next flag from the mode of the following packet). Identification and comment headers are synthesized. Channel order is the WAV mask order; no remapping.
- The codebook library is `packed_codebooks_aoTuV_603.bin` from github.com/hcs64/ww2ogg, downloaded at configure time (`cmake/Dependencies.cmake`, SHA-256 pinned) and turned into a generated C array in the build tree. libogg 1.3.5 and libvorbis 1.3.7 come through FetchContent and are compiled into `pt_vorbis`, linked through `pt_thirdparty`.
- Seeking: at load the packets are indexed (offset, size, block flag from the mode number in the first byte, start sample: a packet yields previous block / 4 + current block / 4 samples, the first yields none). A seek restarts the decoder one packet before the target and discards samples, which reproduces the linear decode exactly. IMA and PCM seek by block and frame.
- Verification (`pt_audio_test --decode-all`, against the vgmstream r2117 WAVs in `dump/audio`, all 313 bank media and the 5 demo streams): PCM 97 media, 0 of 3,094,349 samples differ; IMA ADPCM 33 media, 0 of 3,050,624 differ; Vorbis 188 media, 107,004 of 916,366,169 samples (0.012 %) differ by 1 LSB, maximum error 1 LSB. vgmstream converts Vorbis float output with `(int)(f * 32767.0f)`; the remaining 1 LSB differences are float rounding between the two libvorbis builds. Seeks to four positions per media reproduce the linear decode bit for bit. All 313 bank media load in about 0.1 s (headers rebuilt, codebooks built once per media).

### Engine model

- Threads: the game thread calls `SoundSystem`; every call becomes a command in a mutex-protected vector, swapped out by the render call. The render call (SDL callback, or `RenderOffline` when no device is open) owns all engine state. `PostEvent` returns its playing id at once; live ids and per-event counts sit behind a second small mutex (`IsPlaying`, `IsEventPlaying`). Marker and end notifications are queued by the render call and delivered by `Update(dt)` on the game thread. No heap allocation per block in the mixer; voices allocate when created.
- Timing: 48 kHz, 256-frame blocks. Delayed actions, container items and music segments start at their exact sample inside a block. A voice that ends inside a block lets its container start the next item in the same block, so SampleAccurate transitions are gapless; a Disabled transition waits for the end of the eboot's 1024-frame audio frame in which the item ended (Decisions).
- Events: each action runs at post time plus `DelayTime` (+ random range). Supported: Play (TransitionTime fade-in with its curve), Stop, Pause, Resume (fades with curves, run as the eboot's transitions, Decisions; scopes E, E_O, ALL, ALL_O, AE, AE_O with exception lists of nodes and buses), SetState, SetSwitch, SetGameParameter and ResetGameParameter (Independent or Offset, random range, transition), SetAkProp Set and Reset for volume, pitch, LPF and bus volume (per object or for all objects; persistent until reset, as in Wwise), Mute and Unmute, Break, Seek (absolute ms or fraction of the duration, random range). A Stop also cancels pending Play actions on the stopped targets. Stop on a voice created in the same instant fades it like a playing voice. `SoundSystem::StopPlayingId` stops a playing id over a fade along an AkCurveInterpolation curve (the effect sound node's release, `formats/vfx.md` section 7). `SoundSystem::SeekPlayingId` moves the voices of a playing id to a time of their media (a demo on another demo's clock, `demo.md` section 10, functor 0xD4BA82456D41).
- Hierarchy: a voice sums Volume, Pitch, LPF, MakeUpGain, OutputBusVolume, game and user aux send volumes over its node and all parents, plus node RTPCs, SetAkProp offsets, node state offsets and layer RTPCs. Output bus: first `override_bus_id` up the chain (Master Audio Bus when none). Positioning, game aux, user aux, voice limit and virtual voice settings come from the first node that overrides its parent, else from the top node. Randomizers and InitialDelay (seconds) of a Sound or container are rolled when that node is played (a continuous container rolls once for all its items); actor-mixer randomizers are rolled per voice.
- Containers: RanSeqCntr step mode picks one child per play (sequence position and avoid-repeat history kept per container, per object when not global; weights; shuffle pool). Continuous mode plays the playlist (12 entries for `Play_sfx_clock_bell`, not its 5 children), loop count 0 is infinite, transition Delay waits `time + random(mod_min, mod_max)` ms, TriggerRate starts items at that period, Disabled starts the next item at the first multiple of 1024 frames after the item's start at which its last voice has ended, other modes when the last voice of the item ends. SwitchCntr uses the object's switch (global object's value as fallback, then the default switch) or the global state for state groups. LayerCntr plays all children; layer RTPCs apply to associated children and the crossfade curve (y 0..1, linear gain) follows the crossfade RTPC.
- Music: MusicRanSeqCntr playlist tree (groups and segment leaves with loop counts, 0 infinite; random groups shuffle). A segment starts its track clips at `entry` (smallest marker) and schedules the next segment at `start + exit - entry` (largest marker); clips play source `[play_at + begin_trim, play_at + duration + end_trim)` placed on the segment timeline, and later clips carry past the exit marker. Random and sequence tracks pick a sub-track per segment play. `Play_bgm_corridor_f110`: segment 228569821 at 0.000000 s, segment 1047821718 at 42.500000 s and again at 292.500000 s. A Pause action holds a playlist's and a container's schedule with its voices (Wwise pauses the playing instance): the next segment or item waits, and a Resume moves its time and the start of voices scheduled but not started by the length of the pause. Before, the timer of a paused playlist still started the next segment, unpaused: the option screen's `Pause_All` silenced the f110 corridor music until its next segment boundary (42.5 s after it started, then every 250 s), where it came back in the menu. Check (`--audio-capture`, f110 maze A, the menu open 45 s from 31.5 s): before, silent from 35.5 s and the music back at 60.5 s with the menu open; now silent to the close at 76.5 s.
- Voices: Sound Loop 0 infinite, n plays; with `smpl` loop points the first pass plays to the loop end (exclusive end = dwEnd + 1), repeats loop the region, the last pass continues to the end. Markers fire whenever playback crosses them, including loop passes. Tone Generator (sine, triangle, square, saw, white and pink noise, sweep, fixed or envelope mode) and Silence sources read their parameters from the FxCustom object whose id is the source id. The external source Sound plays media handed to `PlayStream`. FeedbackNodes (company 0, motion device 406, Motion Generator source) play as motion voices without audio: once per block each voice samples its two curves at the voice time (curve time = t / period multiplier, wrapped at the period; times the ADSR envelope for duration type 2), multiplies by the voice volume chain and fades and clamps at 0; the sums per motor are quantized as the PS4 rumble device 0x5E24C0 (above 1 is 255, else value * 255 truncated) into `SoundEngine::Motion()`, which the game sends to the pad (`gameplay.md` 14.5, 14.7). A motion voice lasts the generator's duration and follows containers, pauses and stops like a sound. Global limit from STMG (256): a new voice steals the oldest voice of strictly lower priority, else it is refused (a container whose item is refused retries a bounded number of times, then stops). Per-node max instances with kill newest or stop oldest; stopping the oldest also ends a continuous container that owns it. At most 512 voices are created per block. Below the STMG threshold (-80 dB, loudest of dry and sends): KillVoice ends the voice and the continuous sequences that play it (Decisions), SetAsVirtualVoice stops rendering and resumes from the beginning, from the elapsed time (loop aware) or from the paused position.
- Mixing: pitch by linear interpolation between the two input frames around a 16.16 fixed-point index, 16-bit fraction (resamplers 0x605BC0 to 0x608440, chosen by 0x605210 from mode and format); the step is `(int)(exp2f(pitch / 1200) * source rate / 48000 * 65536 + 0.5)` with the pitch clamped to 2400 cents either way (0x604E60), a pitch change ramps the step linearly over 1024 frames (0x606400), and a step of exactly 0x10000 copies the input. Voice LPF: second order Butterworth low pass (0x60B9B0) at the cutoff of 0x636E60 (lpf below 30: 20 kHz down to 7 kHz linearly, `(30 - lpf) * 433.33 + 7000` Hz; from 30: `16.797 * 2 ^ ((100 - lpf) * 0.12433)` Hz), frequency capped at 0.45 of the rate, bypassed at 0.1 and below, coefficient changes ramped over 8 sub-blocks of 128 samples; the node LPF and the attenuation, cone and obstruction LPFs combine by maximum (0x5F3240). Downmix to stereo by channel mask: FL and FR 1, FC 0.707 to both, back and side 0.707 to their side, LFE 0.5 to both, back center 0.5. 3D game-defined: emitter from `SetObjectTransform` (an object without a transform is at the listener), listener frame from the camera forward and up with pitch and roll, azimuth `atan2(side, front)` and elevation in that frame (0x5807F0); attenuation curves VolumeDry, VolumeAuxGameDef, VolumeAuxUserDef and LowPassFilter at the distance, Spread at distance * cos(elevation) (0x5F3240); cone volume linear in dB over the angle, cone LPF; 7.1 panning from the pan table of 0x58DBC0 (power pairs between speakers at 30, 100 and 142.5 degrees, defaults of 0x58FCA0, a center segment when Center % is set); spread as `(int)(width / 43 + 1) + 1` virtual points over spread% * 360 degrees whose powers are averaged (0x58E0F0, 0x58E340; the speaker angles are rounded to 512ths by 0x58FCD0, 43, 142 and 203, and the 43 is its smallest gap between them; audio_sd_f040's `cry_s01` matches this panner per channel within 0.22 dB, Reference captures); the 7.1 gains then fold to stereo with the downmix above. Multichannel spatialized voices pan each channel on its own arc; non-spatialized 3D voices keep the 2D mapping. 3D user-defined: the path vertices are listener-relative (x right, z forward), one path per play (random or sequence by path mode) with the random range offset. 2D with panner: PAN_LR balance.
- Buses: bus volume = BusVolume prop + state BusVolume + RTPC + SetBusVolume + ducking; voice volume, pitch and LPF from Volume/Pitch/LPF props, states and RTPCs of the whole bus chain apply to every voice routed through it. States transition linearly in dB over the STMG time for the (from, to) pair or the group default. Ducking: while voices play on the ducking bus the target bus ramps to the duck volume over fade out, and back over fade in after the recovery time. Aux sends: game-defined sends per object (`SetObjectAuxSends`; an object that never received a list uses the global object's) scaled by GameAuxSendVolume and VolumeAuxGameDef; user-defined sends from the node's four aux buses. The bus gain is applied before the bus effects, then effects, then the mix goes to the parent. Effects on aux buses do not pass the dry signal. Effects on buses: RoomVerb, Stereo Delay and Matrix Reverb as the eboot's plug-ins (Decisions), Peak Limiter on the master (threshold -1.5 dB, ratio 10, 10 ms lookahead, 100 ms release, adds 10 ms latency, detects the master's 7.1 channels through a side chain, Decisions). Effects run while a bus receives signal or its tail lasts (reverb decay, delay feedback, twice the limiter lookahead so its delay line drains) and are reset when the tail has passed.
- Demo stream audio: `PlayStream` posts event `0xAE3819F7` (posted by the eboot at 0x77341C), whose only Sound is the external source, top level, 2D, on bus 3319603847 (-6 dB, muted by `state_common` splash_screen and game_over, not by `cutscene_state`). ### Decisions

- Bus volume before the bus effects: the Master Audio Bus is +3 dB and its limiter works at -1.5 dB; with the gain after the limiter loud events would clip.
- dB to gain as the eboot does it where its path is traced: FUN_005a0fc0 turns a voice's volume (its own and its buses' Volume, PBI +0xC0 and the modifier block +0x12C) and its output bus volume (+0xE4, +0x128) into gains with the cubic fast 10^x, one conversion each (FastPow10: 27866352 x + 1.0653532e9 as float bits, 0.999039 at 0 dB, within 0.02 dB elsewhere), and 0x59F978 (in 0x59F800) the make-up gain (+0xD4, RTPC parameter 0x24) on its own; the bus volume setters 0x59D1E0 and 0x59D2C0 do the same for the bus volume, and the limiter's gain (0x5AE4B0) uses it too. A 0 dB voice so carries 0.999039 three times, and each bus on its way with a 0 dB volume once more. The distance attenuation and obstruction curves are gains (1 + y): the ENVS loader 0x56D890 adds 1 to the points of a dB volume curve and evaluates it as linear, and 0x5F2FC0 multiplies the attenuation's volume curves into the ray gains as they come out of the curve evaluator 0x11A8BB0, which for a dB curve would return decibels (inferred: a curve interpolated in dB would put audio_sd_f040's cry 6 dB lower than the capture). P.T. never sets obstruction or occlusion. The cone's share of its outside volume becomes a gain with the fast 10^x on the dry ray only (0x5F2FC0). Aux sends (0x581880): a game-defined send's volume (PBI +0x10C) and each user send's volume (+0xEC) go through the fast 10^x, the game-defined one times its object's level, and reach the aux bus with the voice's own gain (voice volume and make-up gain), the aux attenuation curve and the occlusion; the aux bus's own voice volume is not traced and stays exact. Conversions not traced yet stay exact (DbToGain) (Open).
- Peak Limiter as the eboot's plug-in (confirmed, 0x5AD9C0 setup, 0x5ADC60 execute, 0x5AE4B0 linked channels): the input is delayed by the lookahead (48000 * 0.01 = 480 frames); each frame's channel peak is held for the lookahead unless a higher one comes, and sets the target max(20 log10(peak) - threshold, 0) dB through a fast log (exponent and a series in the mantissa); a dB envelope follows it with attack exp(-2.2 / (lookahead / 2)) while rising and release exp(-2.2 / (rate * release)) while falling; the gain is the eboot's fast 10^x of (1 / ratio - 1) * envelope / 20, which is 0.99904 (-0.008 dB) at rest, so everything through the master bus carries it. The eboot's master runs in 7.1 and the limiter links all eight channels (processLFE 1, channelLink 1), so its detector is the largest channel of each frame. The port's master is stereo, and a detector on the fold limits where the original does not (gc_p07_030 folds to +1.6 dBFS peaks while its 7.1 channels stay at -3.3 dBFS: up to 2.76 dB of gain reduction, 0.97 s of it above 0.5 dB). So the engine keeps the master's 7.1 channels as a side chain for the detector (`SoundEngine::sc_`, `Effect::SetDetector`) and applies the limiter's gain to the stereo mix: a 2D mono or stereo voice adds its bus contribution on FL and FR; a spatialized mono voice adds its signal times its seven speaker gains; a voice with more channels keeps them apart through the resampler and the voice low pass and adds each to its own speaker (2D, LFE included) or through that channel's speaker gains (spatialized). Each contribution carries the gains of the buses on its way to the master and goes in only through buses without effects; a bus with effects (the aux buses) adds its stereo output on FL and FR. lisa_kill confirms it (Reference captures): over the 0.93 s where a detector on the fold would cut more than 0.5 dB, the capture holds the stream at 0.69979 on every channel with a residual of -86.6 dB (-18.1 dB against the stream limited on its fold).
- Effects on an AuxBus mute their dry level (confirmed, 0x5AFB50 and 0x5B1420 run them as send effects): the RoomVerb and Matrix Reverb share sets hold dry 0 dB, yet in radio_subtitles_rb the radio's direct part is the dry path alone although its passage send is 6 dB louder.
- RoomVerb follows the eboot's plug-in (confirmed, 7.1 process 0x5B3950): mono input (L + R) / sqrt(6) of the bus (the plug-in sums the six non-center speaker channels, so the send of a spatialized mono voice carries its non-center 7.1 gain sum instead of the folded stereo gain); tone filters at their positions (3 input, 1 early reflections, 2 reverb; low shelf, peaking, high shelf, Butterworth low and high pass, band pass, notch); pre-delay; early reflections from the pattern tables of the patterns P.T. uses (10, 13, 24 at 0x13B4FE0 to 0x13B7FD0) scaled by 2 ^ (room size / 100), the rear pair delayed by the front/back delay; four diffusion allpasses; units of four lines whose lengths are odd primes distinct from the previous one (0x5B49A0), spread by density and room shape with the LCG `x * 0x0BB38435 + 0x3619636B`; cumulative per unit input delays; Jot damping from decay time and HF damping with the plug-in's clamp; a DC blocker per output pair; width, front, rear (+3 dB fold) and center levels, reverb level - 3 dB. Stereo Delay follows the eboot's plug-in (confirmed, 0x62A990 with the delay lines of 0x5DA7D0): each side reads its input channel (type 0 the front left or right channel, 1 the center, 2 (side + center) * 0.707, 3 none; the port takes (L + R) / 2 for 1 and 2), its line is floor(rate * time) samples rounded up to a multiple of 4 and at least one 1024-frame buffer (0x5DA540, 0x5D9780), each sample the line takes input + feedback * own echo + crossfeed * other echo through the filter (plug-in filter type - 1 into the biquad designer above: P.T.'s type 7 is a notch at 835 Hz, Q 1), and the echo goes to the front pair times wet (front/rear balance as constant power, -100 = front only in P.T.). Because the delay reads only the front pair of the 7.1 bus, the send of a spatialized mono voice to it carries the voice's FL and FR gains, not the folded stereo. Only events 5252493F and BA6F9BBE send to it (containers 195195747 and 939944219 override their parents' user aux sends with it). Lisa's cry containers (303456639 for `Play_voice_ene_cry_s_01`, 14758199 for `_f020`) list it too but do not override, and their parent, actor-mixer 862628444, has no user aux sends, so the cries never reach it, in the original as in the port (audio_sd_f040, Reference captures). Matrix Reverb follows the eboot's plug-in (confirmed, plug-in 0x73 registered by 0x54CA20: effect 0x5B8550, parameters 0x5C4C40 and 0x5C4DD0, setup 0x5B8770, execute 0x5B8EE0, damping 0x11AB840, the generic 16-line process 0x5C3FD0): 4, 8, 12 or 16 lines of the default lengths 0x13B9AA0 (13.62 to 30.86 ms) or the custom ones, each rate x time rounded up to odd and then to the next number without a divisor from 3 to its root, sorted; per line g = 0.001 ^ (length / rate / reverb time) and a one-pole low pass y = b y + g (1 - b) x with b = (1 - hfRatio^2) log10(g) ln(10) / 4 (0x1C365F0), the factor clamped so that the longest line's b is 1; the lines take the sum of the bus channels (the LFE only with processLFE) through a 10 Hz DC blocker (pole 1 - 2 pi 10 / rate), the pre-delay and Jot's tone correction (1 - beta z^-1) / (1 - beta), beta = (1 - 1 / hfRatio) / (1 + 1 / hfRatio); each line is fed the next line's output plus -2 / count times the sum of all outputs (Householder with a shift); each channel takes the lines with the signs of 0x13B98A0 (rows FL, FR, FC and the surrounds, the LFE last), times wet, and the port folds them to stereo like the voices and feeds the lines L + R (the send of a spatialized mono voice carries its 7.1 gain sum, centre included). In P.T. it never sounds: its only listed sender, the puzzle clear chime `0xF27DAC95` (Sound 118929891), does not override its parent's user aux sends, so it sends to the parent's 4251101266 as the port does (renders of the chime match before and after, -26.5 and -67.7 dBFS rms in its first two seconds); the plug-in's impulse response (P.T.'s 16 lines, 3.6 s, hfRatio 9.1, wet -20 dB, pre-delay 50 ms): -16.7, -25.5, -32.0, -37.5 dB per 250 ms after the first quarter second, against -35.1, -40.9, -45.9, -50.8 dB of the port's former feedback delay network.

### pt_audio_test

`pt_audio_test [--game DIR] [--dump DIR]` with one mode:

- `--decode-all`: decode every media and the five demo streams, compare with `dump/audio`, check seeks.
